# 김서현 활동 기록

- 학번: 20262688
- 이름: 김서현

## 활동 기록

### 1~3주차

- GitHub 팀 저장소 생성
- 팀원 구성 및 기본 정보 정리
- `README.md` 작성
- 팀원별 개인 활동 기록용 `.md` 파일 생성
- `members` 폴더 및 기본 파일 구조 구성

### 4~5주차

- 팀 프로젝트 진행 방식에 대한 회의 진행
- 보고서 작성 방식과 소프트웨어 개발 방식의 특징 비교
- 팀원들의 의견을 정리하여 소프트웨어 개발 방식으로 프로젝트 방향 결정
- 회의 내용을 정리하여 Markdown 형식의 회의록 작성
- 이후 프로젝트에서 사용할 GitHub 활동 기록 방식 정리
- 팀원들에게 개인 `.md` 파일 작성 방법 안내
- `Edit this file`을 이용한 Markdown 파일 수정 방법 설명
- `Commit changes`와 Commit message 작성 방법 안내
- 각 팀원이 자신의 GitHub 계정으로 직접 활동 기록을 남기는 방법 공유
- 팀원별 활동 기록과 회의 기록을 지속적으로 관리할 수 있도록 저장소 구조 정리

### 6주차

- 프로젝트 주제 선정을 위한 회의 진행 및 주요 논의 항목 정리
- 팀원들에게 자유롭게 프로젝트 아이디어를 제안하도록 요청하고 의견 취합
- 도서관 자리 확인 앱, 학습 일정 관리 웹앱, 마감 관리 앱, 강의계획서 분석기, 점메추 프로그램 등 총 5개의 후보 아이디어 정리
- 사용자의 최근 식사 정보, 이동 거리, 음식점 정보 등을 활용하는 점메추 프로그램 아이디어 제안
- 팀원들의 의견을 다시 확인하여 최종 프로젝트 주제를 점메추 프로그램으로 결정
- 점메추 프로그램의 핵심 기능과 개발 방향 정리
- 프로젝트 개발 언어를 Python으로 정하는 과정에 참여
- 회의 내용을 정리하여 GitHub 회의록 작성
- 다음 회의에서 역할 분담, 사용할 API 조사, GitHub 협업 방법을 우선적으로 결정하도록 안건 정리

### 7~8주차

- 중간고사 기간으로 인해 정식 회의 대신 간단한 진행 상황 확인 회의 진행
- 기존에 결정한 `점메추 프로그램` 프로젝트 방향과 Python 사용 계획 재확인
- 음식 및 음식점 정보를 활용할 수 있는 공공데이터 API 후보 조사
- 공공데이터포털을 중심으로 음식점 정보, 음식 분류, 영양정보 관련 데이터 확인
- GitHub 협업 방식을 단순화하여 팀원별 작업 분리, Commit, main 통합 방식으로 정리
- 역할 분담과 최종 API 선정은 9주차 회의에서 결정하도록 다음 안건 정리
- 7~8주차 활동 내용을 GitHub 회의록에 정리

### 배운 내용

GitHub 저장소를 직접 생성하고 README와 Markdown 파일을 이용해 팀 프로젝트의 기본 구조를 구성하는 방법을 익혔다.

또한 팀 회의를 통해 프로젝트 진행 방향을 정하고, 그 과정을 회의록으로 남기면서 GitHub가 단순히 파일을 저장하는 공간이 아니라 프로젝트 진행 과정도 기록할 수 있는 도구라는 점을 알게 되었다.

팀원들에게 Markdown 작성과 Commit 방법을 설명하면서 GitHub를 활용한 기본적인 협업 방식도 익혔으며, 각자의 활동을 꾸준히 기록하는 것이 중요하다는 점을 배웠다.

여러 아이디어를 단순히 제안하는 것에서 끝나는 것이 아니라 데이터 확보 가능성, 구현 난이도, 개발 기간 등을 비교하여 실제로 구현 가능한 주제를 선택하는 과정이 필요하다는 점을 알게 되었으며, 프로젝트 주제를 정한 이후에는 핵심 기능과 개발 언어뿐만 아니라 역할 분담, API, GitHub 협업 방식까지 빠르게 정해야 실제 개발을 시작할 수 있다는 점을 알게 되었다.
